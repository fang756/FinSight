# 2026-05-28 工作日志

## FinSight 项目进展

### 预测线残留问题修复
- **问题**：用户训练完平安银行后，再训练万科A，K线图上自动显示预测线，但用户还没点击"预测未来价格"
- **根因**：`PredictView.vue` 中 `handleTrain` 训练成功后立即将 `predictionLineData.value = res.data.predictions`，导致回测预测线自动渲染
- **修复方案**：
  1. 新增 `backtestPredictions` ref，训练成功后只存数据不显示
  2. 点击"预测未来价格"后才将 `backtestPredictions` 赋值给 `predictionLineData` 显示
  3. 切换股票时清空所有预测相关数据（predictionLineData、backtestPredictions、futurePredictions、metrics、trainMessage）
  4. 重新训练时也清空所有预测数据

### 后端服务
- FastAPI 运行在 8001 端口，前端 Vite 代理同步配置为 8001

### 万科A训练500错误修复
- **问题**：用户从浏览器训练万科A时报500错误
- **排查**：直接调用后端API返回200正常，说明后端逻辑本身没问题
- **根因**：`lstm_model.py` 的 `train_model` 和 `predict_next` 函数没有 try/except 包裹，任何异常都会导致FastAPI返回500而非友好错误信息
- **修复**：
  1. 给 `train_model` 和 `predict_next` 都加上 try/except，异常时返回 `{"success": false, "message": "训练异常: ..."}` 而非500
  2. Vite代理增加 `timeout: 120000` 配置，防止LSTM训练时间较长时代理超时

### 启动脚本
- 创建了3个bat脚本方便用户自己启动项目：
  - `一键启动.bat`：自动启动前后端+打开浏览器（推荐）
  - `启动后端.bat`：单独启动 FastAPI (:8001)
  - `启动前端.bat`：单独启动 Vite (:3000)
- 之前用 run_in_background 启动的进程有超时机制会被自动回收，导致500错误
- 改用 Start-Process 或 bat 脚本启动的独立进程更稳定
